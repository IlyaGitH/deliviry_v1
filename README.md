# бортовое ПО

## на данный момент реализуется навигацию по лидару на основе карты

Автономное транспортное средство доставки грузов для внутренней логистики
НТЦ АО «АВТОВАЗ». Репозиторий содержит всё ПО робота: прошивку VEX V5 Brain
и пакеты ROS 2 для Raspberry Pi 5.

**Платформа:** Raspberry Pi 5 · Ubuntu 24.04 Server arm64 · **ROS 2 Jazzy** · VEX V5

> Именно Jazzy. Humble привязан к Ubuntu 22.04 и на 24.04 не ставится.

---

## Архитектура: Brain ведёт, Pi видит

```
 ┌───────────── Raspberry Pi 5 ─────────────┐        USB        ┌──────── VEX V5 Brain ────────┐
 │ lidar_node ──/scan──> obstacle_node ──┐   │                   │ маршрут по графу точек        │
 │ vision_node (YOLO11n NCNN + HSV) ─────┤   │  F / T / O / H    │ курс по гироскопу 276-2333    │
 │                                       ├──> v5_bridge ───────> │ знаки, светофор, объезд       │
 │ web_node (заказы) ── M / C / A ───────┘   │ <── E / P / S / K │ застревание, связь, перегрев  │
 │ signal_node ─> light / buzzer / lock      │                   │ 6 моторов, бамперы, экран     │
 └───────────────────────────────────────────┘                   └───────────────────────────────┘
```

Рейс целиком исполняет прошивка Brain: едет по точкам, держит курс
по гироскопу, останавливается у знака, ждёт зелёного, объезжает
препятствия, выходит из застреваний, встаёт на красную разметку точки
и сверяет BLE-метку. Raspberry Pi даёт ей глаза и связь
с заказчиком: распознаёт знаки и светофор, находит препятствия по лидару,
принимает заказ из веб-интерфейса, управляет светом, зуммером и замком.

Почему так, а не Nav2 на Pi: задержки Wi-Fi, DDS и нейросети не влияют
на движение. Если Pi перегрузится или упадёт детектор, Brain встанет на
паузу, но не потеряет маршрут и не поедет вслепую.

## Как робот находит точку

1. **Счисление.** Brain знает координаты точек из карты в прошивке
   и едет к ним по гироскопу и энкодерам. Ошибка копится: 1–2 % пути.
2. **Красная разметка.** За 2,5 м до точки Brain включает поиск
   (`DOCK_SEARCH`). `vision_node` находит красное пятно на полу и по
   высоте и наклону камеры вычисляет его положение относительно робота.
   Brain доезжает до пятна, встаёт на него с точностью около 5 см
   и сбрасывает свои координаты на координаты точки (`DOCKED <точка>
   <исправленная_ошибка_мм>`). Если пятна не видно 3 с — встаёт по
   счислению (`DOCK_NOT_FOUND`), рейс продолжается.
3. **BLE-метка.** На каждой точке лежит телефон. `ble_node` узнаёт его
   по имени или iBeacon и сообщает Brain уровень сигнала. На прибытии
   Brain пишет `ZONE_OK`, `ZONE_MISMATCH` (рядом метка другой точки)
   или `ZONE_UNCONFIRMED`. Сильный сигнал метки цели включает поиск
   разметки раньше. `lock_node` может открывать отсек только при метке
   нужной точки рядом (`zone_policy: require`).

В симуляторе с колесом на 2 % меньше расчётного: без разметки робот
вставал в 43 см от точки, со стыковкой — в 6 см.

### Разметка

Красное пятно на полу, лучше квадрат 40×40 см или больше, матовое:
цветная бумага, изолента в несколько полос, крашеный лист. Центр пятна —
место, куда встанет центр робота. Координаты центра = координаты точки
в прошивке. Другого крупного красного на полу в зоне 3 м быть не должно.

### Телефоны-метки

MAC-адрес телефонов меняется, поэтому метка узнаётся по содержимому
рекламного пакета. Подходит любой из двух способов.

| Способ | Android | iPhone |
|---|---|---|
| По имени | nRF Connect → Advertiser → новый пакет, Complete Local Name, имя Bluetooth телефона `ATSD-KPP` | nRF Connect → Advertiser, Local Name `ATSD-KPP`, приложение на экране |
| iBeacon | Beacon Simulator → iBeacon, UUID `E2C56DB5-DFFB-48D2-B060-D0F5A71096E0`, major 1, minor = номер точки | не поддерживается в фоне |

| Точка | Имя | minor |
|---|---|---|
| КПП | `ATSD-KPP` | 1 |
| Администрация | `ATSD-ADMIN` | 2 |
| Зона тестирования | `ATSD-TEST` | 3 |
| Склад | `ATSD-SKLAD` | 4 |

Проверка: `sudo python3 /opt/atsd/hw_check.py --no-gpio` покажет найденные
метки и уровень сигнала. Порог «рядом» — `near_rssi: -65` в `atsd.yaml`;
положите телефон на точку, встаньте роботом на разметку и посмотрите
реальный уровень в `ros2 topic echo /ble/zone`.

## Прошивка VEX V5

Файл `firmware/vex_v5/src/main.cpp`, собирается расширением VEX для VS Code
(Windows) или веб-версией VEXcode V5.

1. VS Code → значок VEX → New Project → V5 → C++ → Empty Project.
2. Заменить `src/main.cpp` файлом из репозитория. Если в проекте есть
   `robot-config.cpp` с `brain Brain;` — удалить там дубли.
3. Подключить Brain по USB, выбрать слот, **Build**, затем **Download**, затем **Run**.
4. Первые 2 секунды после запуска робот должен стоять: калибруется гироскоп.

Перед первым рейсом, вкладки на экране Brain:

| Вкладка | Что проверить |
|---|---|
| TEST → кнопки моторов | каждое колесо катит робот вперёд, иначе поменять реверс в разделе 3 |
| DIAG | поворот рукой влево — YAW растёт, иначе `GYRO_SIGN = 1.0` |
| TEST → DRIVE 1M | сравнить с рулеткой, поправить `WHEEL_DIAM_MM` |
| TEST → TURN 90 | вписать показанную оценку в `TRACK_EFF_MM` |

**Карта трассы** — раздел 2 прошивки, узлы `NODES` в миллиметрах от
старта. Те же координаты в метрах указать в `DEFAULT_POINTS` веб-сервера
(они нужны только для отрисовки карты).

## Установка на Raspberry Pi

```bash
git clone https://github.com/IlyaGitH/deliviry_v1 ~/atsd_ws
cd ~/atsd_ws/src/atsd_bringup/scripts
sudo bash install.sh --with-yolo
sudo reboot
```

Скрипт ставит ROS 2 Jazzy и зависимости, создаёт пользователя `atsd`,
собирает workspace в `/opt/atsd/ws`, прописывает сервисы и udev-правила,
включает UART0 на GPIO14/15 под GNSS, I2C под X1202, снимает лимит
600 мА на USB. Идемпотентен.

| Флаг | Когда нужен |
|---|---|
| `--with-yolo` | поставить `ncnn` для распознавания знаков (без torch) |
| `--skip-upgrade` | система уже обновлена |
| `--skip-ros` | ROS ставится отдельно |
| `--ros-key=ФАЙЛ` | `raw.githubusercontent.com` недоступен, ключ скачан вручную |

Ключ ROS вручную, если GitHub не открывается:
`curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key -o ros.key`
на машине с доступом, затем `scp` на Pi и `--ros-key=`.

**Модель знаков** положить в `/opt/atsd/models/signs_ncnn_model`
(папка после `yolo export model=best.pt format=ncnn imgsz=640`: внутри
`model.ncnn.param`, `model.ncnn.bin`, `metadata.yaml`), затем
`sudo chown -R atsd: /opt/atsd/models`.

Модель запускается через пакет `ncnn` напрямую (`backend: auto`).
**Не ставьте на Pi `ultralytics` и `torch`:** сборка torch для aarch64 с PyPI
тянет гигабайты CUDA-библиотек, а ultralytics требует numpy 2 и ломает
системные numpy, OpenCV и setuptools из apt. Экспорт модели делайте на
компьютере или в Kaggle, на Pi нужна только готовая папка.

### Если на Pi уже пробовали ставить ultralytics

По одному пакету, чтобы ошибка на одном не остановила остальные:

```bash
for p in ultralytics ultralytics-thop ultralytics-platform torch torchvision triton \
         cuda-toolkit cuda-bindings cuda-pathfinder nvidia-ml-py nvidia-cusparselt-cu13 \
         nvidia-nvtx nvidia-nvshmem-cu13 nvidia-nvjitlink nvidia-nccl-cu13 nvidia-curand \
         nvidia-cufile nvidia-cuda-runtime nvidia-cuda-nvrtc nvidia-cuda-cupti nvidia-cusparse \
         nvidia-cufft nvidia-cublas nvidia-cusolver nvidia-cudnn-cu13 polars-runtime-32 \
         sympy mpmath setuptools; do
  sudo pip3 uninstall --break-system-packages -y "$p" 2>/dev/null
done
sudo apt install --reinstall -y python3-setuptools python3-numpy python3-opencv
sudo pip3 cache purge
python3 -c "import setuptools, numpy, cv2; print(setuptools.__version__, numpy.__version__, cv2.__version__)"
```

Ожидается `68.1.2 1.26.4 4.6.0`.

### Обновление с прошлой версии

```bash
cd ~/atsd_ws && git pull
sudo bash src/atsd_bringup/scripts/install.sh --skip-upgrade --skip-ros --with-yolo
sudo reboot
```

Установщик сам уберёт из `config.txt` устаревшие `dtoverlay=uart2`
(GNSS больше не на GPIO4/5) и `dtoverlay=disable-bt` (Bluetooth нужен
для меток), поставит `bleak` и новый udev. Прошивку V5 обновить до 2.1.1.

## Проверка железа

Без ROS, по очереди каждое устройство:

```bash
sudo systemctl stop atsd.target
sudo python3 /opt/atsd/hw_check.py          # всё, кроме замка
sudo python3 /opt/atsd/hw_check.py --lock   # плюс импульс на замок
```

Скрипт проверит симлинки, спросит у Brain версию прошивки и посчитает
телеметрию, посчитает кадры лидара, прочитает кадр камеры и поищет на нём
красную разметку, найдёт NMEA от GNSS на любой скорости, найдёт
телефоны-метки, прочитает гейдж X1202, плавно зажжёт фары и ленту,
пискнет зуммером, покажет состояние геркона.

Затем всё вместе:

```bash
sudo systemctl start atsd.target
systemctl status atsd-drive atsd-perception atsd-actuators atsd-sensors atsd-web
journalctl -u atsd-drive -f
```

В логе моста должно быть `Прошивка: ATSD-1M 2.1.1` и `Все источники
восприятия на связи`.

## Сценарий доставки

1. Администратор открывает `http://<адрес-пи>:8080`, выбирает «откуда»
   и «куда» (КПП, Администрация, Зона тестирования, Склад) и нажимает
   «Отправить робота». Веб публикует `/mission/start`, мост шлёт `M` на Brain.
   Заказ можно дать и с экрана Brain, вкладка MISSION.
2. Робот едет к точке погрузки. Отправитель по своей ссылке открывает
   отсек, кладёт груз, закрывает крышку и жмёт «Готово» — `C` на Brain.
3. Робот едет к точке выдачи. В пути отсек заблокирован: `lock_node`
   отказывает в открытии, а при открытой крышке (геркон) поднимает тревогу.
4. Получатель открывает отсек, забирает груз, жмёт «Готово». Рейс закрыт,
   таймер остаётся на экране.

Статус заказа берётся из состояния миссии на Brain, а не вычисляется
по расстоянию: робот сам решает, что приехал.

**Отчёт для протокола испытаний:** `GET /api/report/<id>` — общее время,
факт доставки, распознавания знака и светофора, обнаружения и объезда
препятствия, список сбоев и полный журнал событий.

## Протокол Pi ↔ Brain

Текст, одна команда в строке. Полное описание — в шапке прошивки
и в `atsd_drive/protocol.py`.

| Pi → Brain | Смысл |
|---|---|
| `M <from> <to>` | старт рейса, точки 0 KPP · 1 ADMIN · 2 TEST · 3 SKLAD |
| `C` · `A` · `U` | груз подтверждён · отмена · продолжить после сбоя |
| `H` | heartbeat, 10 Гц, только пока жив детектор препятствий |
| `D <вперёд_мм> <вбок_мм>` | центр красной разметки от центра робота, во время стыковки |
| `B <точка> <дБм> <рядом>` | ближайшая BLE-метка, `-1` — нет |
| `F STOP\|CROSS\|BUMP <мм>` | знак и расстояние до него |
| `T R\|Y\|G\|N <мм>` | светофор |
| `O <мм> <L\|R\|B> <глубина> <смещение>` | препятствие и свободная сторона, `O 0` — чисто |
| `X` · `R` · `L <%>` | аварийный стоп · снять · ограничение скорости |
| `V <мм/с> <мрад/с>` | прямое управление вне рейса (совместимость) |
| `N <мм/с> <мрад/с>` | подруливание оператором во время рейса, только для отладки |

| Brain → Pi | Частота | Смысл |
|---|---|---|
| `E degL degR yaw ms mV flags` | 50 Гц | энкодеры, курс, батарея, флаги |
| `P x y yaw v w` | 20 Гц | поза, мм и миллиградусы |
| `S state from to wp/n remain pause t` | 5 Гц | состояние рейса |
| `K EVENT args` | по событию | `ARRIVED_PICKUP`, `STOP_SIGN_HOLD`, `DETOUR_START L`, `DOCKED ADMIN 312`, `ZONE_OK ADMIN -58`, `FAULT STUCK`… |

## Безопасность движения и груза

**Сигнализация** (`signal_node`). В движении горят фары и работает
проблесковый маячок на ленте. При препятствии ближе 1,8 м и после знака
«Пешеходный переход» звучит сигнал о приближении. Задний ход при выходе
из застревания сопровождается отдельным сигналом. На паузе у знака или
светофора лента мигает. При аварии включаются маячок и сирена.

**Токовый интерлок.** Шина 12 В тянет около 1,4 А, соленоид замка берёт
1,1 А. На время импульса `lock_node` публикует `/lock/busy`, `light_node`
гасит свет.

**Heartbeat по живым детекторам.** Мост шлёт `H`, только пока приходят
данные от `obstacle_node` (и `vision_node`, если добавить его в
`require_feeds`). Упал лидар — через полсекунды Brain встаёт на паузу
«NO LINK TO PI».

**Груз.** В пути замок не открыть ни из веба, ни сервисом. Открытие крышки
в пути фиксируется и попадает в журнал рейса. На точке отсек открывается
при BLE-метке этой точки рядом: `zone_policy: warn` — открыть можно,
но в журнале будет `ZONE_UNCONFIRMED_UNLOCK`; `require` — только с меткой.

## Калибровка

**Одометрия и курс** — в прошивке, вкладка TEST на экране Brain
(см. раздел о прошивке). На стороне Pi калибровать нечего:
при `odom_source: brain` поза приходит с Brain.

**Коридор препятствий** — `obstacle_node` в `atsd.yaml`: `front_x`
(передний край корпуса от центра), `half_width`, `laser_x` по реальной
установке лидара. Проверка: `ros2 topic echo /perception/obstacle_info`,
поставить коробку в метре перед роботом.

**Красная разметка** — `vision_node`: `camera_x`, `camera_z`,
`camera_pitch_deg` по реальной установке камеры (по умолчанию как в
статическом TF). Проверка: пятно на полу ровно в 1,5 м перед центром
робота, `ros2 topic echo /perception/spot` должен показать x около 1.5.
Ошибка больше 10 см — поправить `camera_pitch_deg` (дальше, чем есть
на самом деле — угол больше). Если пятно не находится при слабом свете,
снизить `spot_v_min`, если находит лишнее — поднять `spot_s_min`.

## Подводные камни, собранные при развёртывании

Все они уже учтены в коде и установщике. Список нужен, если что-то
пойдёт не так на другой машине.

**`bzip2 : Depends: libbz2-1.0 but it is not installable`**
В образе Ubuntu для Raspberry не было веток `noble-updates`
и `noble-backports`. Установщик теперь проверяет и добавляет их сам.
Вручную: в первой секции `/etc/apt/sources.list.d/ubuntu.sources`
строка должна быть `Suites: noble noble-updates noble-backports`.

**`libexec directory does not exist`**
Нет файлов `setup.cfg` в пакетах. Без них colcon молча не создаёт
исполняемые скрипты узлов. Установщик проверяет их наличие до сборки
и результат после.

**`AMENT_TRACE_SETUP_FILES: unbound variable`**
Флаг `set -u` в `run.sh` ломает скрипты окружения ROS. Теперь `source`
обёрнут в `set +u` / `set -u`.

**`BadPinFactory: Unable to load any default pin factory`**
Два разных источника. Первый — не задана `GPIOZERO_PIN_FACTORY=lgpio`,
на Pi 5 автоопределение не срабатывает. Второй, более коварный —
библиотека lgpio создаёт файл `.lgd-nfy` в **текущем каталоге**,
а у сервиса рабочего каталога не было. Отсюда `FileNotFoundError`
и как следствие отказ фабрики. Лечится `WorkingDirectory=/opt/atsd`
в юните.

**Молчаливое зависание на установке ROS**
`curl` без `--max-time` ждёт вечно, если `raw.githubusercontent.com`
недоступен. Теперь таймаут 25 секунд, скачивание во временный файл
и понятное сообщение с инструкцией.

**Группы не подхватились**
`usermod -aG` действует с момента следующего запуска процесса.
После установки нужна перезагрузка, иначе сервис не получит доступ
к GPIO даже при корректных правах на `/dev/gpiochip*`.

**`lgpio.error: can not open gpiochip`**
Пользователь не в группе `gpio`. Установщик добавляет туда `atsd`,
но своего пользователя надо добавить самому и перезайти по ssh:
`sudo usermod -aG gpio $USER`.

**`ros2 node list` пуст при живых узлах, топики не доставляются**
Fast DDS на связке Raspberry Pi 5 плюс wlan0 ведёт себя нестабильно:
узлы то появляются в списке, то пропадают, а данные по топикам
не доходят вообще, хотя подписки зарегистрированы. Перебор профилей
транспорта, отключение разделяемой памяти и смена режима обнаружения
помогали лишь частично. Решение — **Cyclone DDS**:

    export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp

Установщик ставит пакет и прописывает его и сервисам, и пользователям.
Проверить, что дело именно в транспорте, а не в ваших узлах, можно
штатным примером: `ros2 run demo_nodes_cpp talker` в одной сессии
и `ros2 topic echo /chatter` в другой.

**`ros2: command not found` в новой сессии**
`/etc/profile.d` не читается интерактивной ssh-оболочкой — только
login-shell. Поэтому установщик дописывает в `~/.bashrc` строку
подключения `/etc/profile.d/atsd-ros.sh`. Для нового пользователя
она попадает из `/etc/skel/.bashrc`.

**`Permission denied` на `/opt/atsd/ws/install/setup.bash`**
Каталог принадлежит системному пользователю. Установщик открывает
его на чтение через `chmod -R a+rX /opt/atsd`.

**Обнаружение узлов по вайфаю**
Режим `SUBNET` держится на мультикасте, а точки доступа его часто
режут. Поэтому задан `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST`:
все узлы живут на одной машине, обнаружение не зависит от роутера,
топики не утекают в сеть. Обратная сторона — с ноутбука по сети
к топикам не подключиться, отладка только по ssh.

---

**`/dev/v5` не появляется, хотя Brain виден в `lsusb`**
В старом правиле в одной строке стояли `ATTRS{idVendor}` и
`ATTRS{bInterfaceNumber}`. udev ищет все `ATTRS` у одного родителя, а эти
атрибуты лежат у разных (`usb_device` и `usb_interface`), — правило не
срабатывало никогда. Теперь сравниваются `ENV{ID_VENDOR_ID}` и
`ENV{ID_USB_INTERFACE_NUM}`, которые заполняет встроенный `usb_id`.
Проверка: `udevadm info -q property -n /dev/ttyACM1 | grep ID_USB_INTERFACE_NUM`.

**`Cannot uninstall numpy 1.26.4, RECORD file not found` при установке ultralytics**
pip пытается заменить системный numpy на numpy 2 и по пути успевает
удалить системный `setuptools` и поставить CUDA-пакеты. Лечение — в разделе
«Если на Pi уже пробовали ставить ultralytics». Модель запускается через
`ncnn` без torch.

**Робота заносит на прямой в случайный момент**
Две причины, обе закрыты в прошивке 2.1.1. Перепутанный знак гироскопа
превращает удержание курса в раскачку: отклонение растёт, пока робота
не развернёт. Прошивка сверяет направление поворота по гироскопу и по
разнице бортов и сама переворачивает знак (`GYRO_SIGN_FLIPPED set
GYRO_SIGN +1` — впишите это значение в `cfg`, чтобы не ждать первого
поворота). Вторая причина — «долг курса»: схема 6×6 поворачивает
медленнее команды, и после поворота регулятор доворачивал разницу уже
на прямой. Теперь удержание курса работает только на прямой, ошибка
ограничена 12°, доворот — 0,8 рад/с. Выбросы старого гироскопа при
прямом ходе колёс отбрасываются (счётчик `sp` на вкладке DIAG).

**`reference to 'event' is ambiguous` при сборке прошивки V5**
В SDK VEX есть классы `vex::event` и `vex::light`, а `using namespace vex`
делает их видимыми глобально. Весь код прошивки лежит в `namespace atsd`.

**`call to member function 'printAt' is ambiguous`**
У `Brain.Screen.printAt` две перегрузки, и строка `"%s"` подходит и как
формат, и как `bool`. Вызывать с явным `bOpaque`: `printAt(x, y, true, "%s", s)`.

## Веб-интерфейс

`http://<адрес-пи>:8080`. Роли различаются ссылкой:

| Ссылка | Кто | Что может |
|---|---|---|
| `/` | администратор | создаёт заказ, отменяет рейс, продолжает после сбоя, расставляет точки на карте |
| `/?role=sender&order=ID` | отправитель | открывает отсек на погрузке, подтверждает загрузку |
| `/?role=receiver&order=ID` | получатель | открывает отсек на выдаче, подтверждает получение |

На экране: карта с ровером, этапы доставки, таймер рейса, время до точки,
причина паузы («красный сигнал светофора», «препятствие впереди»),
журнал рейса по-русски, заряд обеих батарей, крышка отсека, связь с роботом.

Подложки карт кладутся в `atsd_web/static/maps/`, привязка — `DEFAULT_MAPS`
в `server.py`. Без файлов рисуется метрическая сетка.
